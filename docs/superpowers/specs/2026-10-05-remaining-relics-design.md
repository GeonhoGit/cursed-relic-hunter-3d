# 미구현 유물 30종 확장 설계

작성일: 2026-10-05. 상태: 사용자 검토용. 구현 전 설계 문서다.

## 1. 목적과 승인된 범위

사용자는 원본 기획서에 있는 유물 중 현재 게임에 추가되지 않은 유물만 추가하도록 요청했다. 2026-10-05에 제안한 30종과 필요한 아군 전환·설치 벽·미끼·포털·구덩이·바닥 아이템·잠금방·보상 예약·재전투 지원 범위를 승인했다. 이 문서는 그 범위를 구현 가능한 계약으로 구체화한다. 목표는 이름만 추가하는 것이 아니라 실제 효과, 획득 조건, 화면 표시, 저장·재접속까지 작동하는 것이다.

기준 자료는 프로젝트 상위의 `저주받은_유물_사냥꾼_상세기획서_v1.0.md`다. 파일명과 달리 본문 기준은 v1.3이다. 개발 기록이 참조하는 v1.4 원본은 현재 제공되지 않았으므로 이 문서에서 v1.4와 동일하다고 주장하지 않는다. 주요 계약은 원본 §4.2, §5~8, §12~13, §16을 사용한다.

추가 ID는 R06/R09/R10/R14/R15/R16/R17/R18/R19/R21/R22/R23/R24/R26/R27/R28/R29/R31/R32/R33/R34/R35/R36/R37/R39/R40/R41/R42/R47/R48이다. 총 30개이며 기존 27종을 합쳐 57종이 된다. 기존 R44~R46은 바람 깃털·도약의 장화·진동의 발굽으로 유지한다. 따라서 기획서의 굶주린 문·맹세의 사슬·무덤의 씨앗은 이번 추가 목록에 포함하지 않는다. 현재 R49~R57, 네 무기, 기존 피해 조정, 점프·Shift 회피, 등급 추첨과 자동 화질 설정도 유지한다.

이번 범위에는 위 유물을 작동시키기 위한 기능을 포함한다. 기획서 전체의 13방 구성, 정예 시스템, 다중 웨이브, 36개 방 템플릿, 연습장과 전체 키 변경 UI를 완성하는 작업은 별도다. 실제 제공되는 콘텐츠 수와 적용한 차이를 README/IMPLEMENTATION에 기록한다.

## 2. 공통 적용 규칙

- 전투는 60틱/초다. 아래 시간은 시뮬레이션 틱으로 환산하며 정지 중 감소시키지 않는다. 일시정지·재접속으로 타이머를 초기화하지 않는다.
- 월드 1u는 현재 3D 변환의 0.04m다. 거리·반경은 원본 u 값을 사용한다. 시점 기반 기본 사격은 상하 조준을 유지한다.
- 이 확장에서 D는 발사 시점의 현재 기본탄 한 발 피해다. 영구 투자와 기존 기본 공격력 유물, 플레이어 약화를 반영한 스냅샷을 사용한다. 발사 총피해는 D×무기 기본 탄환 수다. 기존 무기의 피해를 원본 수치로 되돌리지 않는다.
- 새 고정 피해 효과는 생성할 때 `playerDamage`로 약화를 반영한다. 아군은 원래 적 공격의 독립 피해를 사용하며 플레이어 약화를 상속하지 않는다.
- 적중 순서는 기존 방패/무적 판정 → 기본 피해 → 화상·동결·침묵 → 번개·중력·분열 → 관통 잔량이다. 새 피해 출처는 자신의 허용 효과만 실행하고 기본탄 효과를 재귀 호출하지 않는다.
- 모든 효과에는 고정 ID와 출처를 두어 같은 사건을 두 번 처리하지 않는다. 타깃 거리 동률은 ID순, 안전 위치 동률은 고정 후보 순이다. 전투 판정에서 렌더 시간과 임의 난수를 사용하지 않는다.
- 획득 이력은 소모·상실 후에도 남겨 같은 탐험의 재획득을 막는다. 유물 상실은 그 유물의 활성 설치물/예약을 정리하며 R17 전환 적은 살아 있으면 적대 상태로 복귀한다.
- 레이저·광선은 선분과 3D 높이로 검사하고 첫 벽에서 멈춘다. 새 지상 장판은 시각 영역과 같은 수평 범위·높이 한계를 사용한다. 기본탄과 다른 효과의 판정이 어긋나지 않도록 별도 높이 조건을 공유한다.

## 4. 전투와 설치물 구조

`relic-effects`는 기본 사격/적중/피격/회피/클리어 훅을 소유하고, 효과 계열별 순수 모듈에 위임한다. 정의·수치·조건을 한곳에 모으고 World와 HUD는 이를 참조한다. UI가 직접 상태를 바꾸지 않고 진행 규칙의 성공 결과를 저장한다.

- 생성 탄환: 공전/방출 상태와 잔여 틱, 발사 누적0~3, 피해 스냅샷을 저장한다. 분열·공전탄의 도탄/관통/유도 상속과 재발동 금지를 공통 피해 출처 정책으로 검사한다.
- 번개/중력/광선/가시: 독립 재사용 타이머·고정 ID·직접/지속 피해 출처를 사용한다. 기둥 보호막과 단계 무적은 기존 공통 피해 게이트를 따른다. 광선은 유효 공격 가능한 심장 기둥에도 적중한다.
- 설치 벽: 현재 정적 지형에 동적 충돌체를 합성한다. 몸체·탄환·조준 시야·길 찾기·스폰·포털 설치가 같은 장애물 목록을 사용한다. 설치 전 출구 접근 가능성을 검사한다. 적 기본탄·근접·폭발의 벽 피해는 직접 피해로 적용하고 지형 파괴가 다른 유물 효과를 발동시키지 않는다.
- 아군/미끼: AI에 진영과 유효 목표를 전달한다. 전환 적은 기존 개체 ID/현재HP/적 예산을 유지한다. 아군은 적만 공격하고 플레이어 상태 이상을 주지 않는다. E11 아군은 소환 대신 피해8·속도110·예고42틱·주기144틱 단발 사격을 한다. 전환 종료 시 소환 시도 이력을 유지한다. 보스는 새 아군/미끼를 목표로 삼지 않는다.
- 포털: 한 틱의 가장 이른 벽/몸체/포털 교차를 비교한다. 출구 위치 검증 후 남은 이동을 계속 계산한다. 순간이동 구간을 몸체 충돌 선분으로 취급하지 않는다. 벽 내부 출구는 설치 단계에서 거부한다.
- 회복품 시전/은신/흡수: 입력 소비와 행동 게이트를 공통 루프에서 처리한다. 이동·발사·회피 차단 원인을 HUD에 표시한다. 실패 입력에는 사유를 표시하고 쿨다운을 소비하지 않는다.
- 방 이동·보스 단계/사망 정리·유물 상실은 활성 효과의 명시적 종료 사유다. 지도·설정·탭 숨김은 종료 사유가 아니다. R40 첫 문은 원본의 명시 취소 규칙에 맞춰 Esc 취소를 수행하지만 완성된 한 쌍은 일시정지 동안 유지한다.

## 5. 구덩이·바닥 아이템·잠금방

새 탐험은 `layoutVersion: 2`를 사용한다. 기존0~10 방 ID와 보스/제단/상점 역할을 유지하고 ID11 잠금 보물방을 유효한 선택 분기의 잎으로 추가해 지역당12방이 된다. 시드 기반으로 후보 위치를 선택하며 보스의 단일 입구와 기존 통로 연결을 보존한다. 구 버전 탐험의9/10/11방과 방문한 지형은 확장하지 않는다. 구 탐험에 새 전용 시스템이 없으면 R35/R28/R47은 등장 조건에서 제외한다.

구덩이는 새 지형 버전의 일반 전투방 중 지역당 한 방에 안전한 우회로가 있는 폭80u의 선택 횡단 구간으로 배정한다. 문·중앙 안전 구역·적 생성점·설치물과 겹치지 않는다. 기본72u 회피로는80u 횡단을 완료할 수 없고 R28의108u 회피로 안전한 두 가장자리를 연결할 수 있다. 유물 없이도 우회할 수 있으므로 필수 유물을 강요하지 않는다. 공중 점프는 기존 수직 물리를 쓰고 지상 착지가 유효하지 않으면 마지막 안전 땅으로 복귀해 피해10·기본 피격 무적을 적용한다. 낙하 반복과 피해·방 클리어 재진행을 막는다. 적의 이동/스폰은 구덩이를 피한다.

새 레이아웃의 최초 일반방 클리어 금화8과 보스 클리어 금화40은 같은 금액의 바닥 보상으로 지급하며 고유 pickup ID를 저장한다. 구 레이아웃은 기존 즉시 지급을 유지한다. 새 레이아웃 일반방 세 곳마다 한 방에HP10 회복품을 추가하고 지정 방·위치를 시드로 고정한다. 기본 수집 반경20, R36이면90이다. 재전투/아군 중복 처치에서 생성하지 않는다. 소유 구역을 떠나면 남은 바닥 보상은 폐기하며 방/지역 이동 전에 미수집 보상을 안내한다. 이는 R36/R39가 실제 게임에서 작동하기 위한 경제 공급 변경이다.

현재 지도는 유물 없이도 연결된 미방문 방의 종류를 표시한다. 새 레이아웃에서는 그런 방의 위치/연결은 표시하되 종류를 미확인으로 표시하고 R31을 얻으면 종류를 공개한다. R48은 전체 방을 공개한다. 구 레이아웃의 기존 지도 표시를 유지한다. 미니맵 캐시에는 지도 공개 유물과 잠금문 상태를 포함한다.

R35의 잠금문은 상호작용 거리와 보유 여부를 확인해 열린 상태/열쇠 소모/프로필 목표 사건을 한 변경으로 확정한다. 잠금방의 상자 규칙과 후보 수는 기존 보물방을 재사용한다. 열쇠 없이 보스까지 도달할 수 있다.

## 6. 보상·왕관·재전투

새 레이아웃에서는 보스의 유일한 입구에 연결된 일반 전투방을 해당 지역의 필수 지정 보상방으로 정한다. 생성 검사에서 그 방을 제거하면 보스까지 연결이 끊기는지 확인한다. 최초 클리어 후 일반 유물 보상1회를 추가한다. 세 지역의 지정 보상을 `(region, roomId, mainPathIndex)`로 순서화한다. 기존 구 레이아웃의 보상 수와 이미 제시된 선택지는 유지한다.

R47은 현재 이후 미개봉 지정 보상2개와 출발 해금 풀 안의 유효한 R01~R30 일반 유물2개가 있을 때만 나온다. 아직 생성하지 않은 다음 지역도 저장된 레이아웃 버전·시드로 결정할 수 있다. 후보 제시/획득 확정에서 같은 대상 선정 함수를 사용한다. 획득 전 A/B 위치와 예약 유물을 확인창에 표시한다.

확정 시 B의 유물 보상을 영구 포기하고 A용 두 ID를 예약한다. 다른 상품/보상은 예약 ID를 제외하며 기존 미확정 후보는 무효 슬롯만 보충한다. A의 후보는 예약2개+일반 추가 후보로3개(R34는4개)를 만들고 서로 다른2개를 지급한다. 첫 선택/남은 선택 수/예약 상태/보상 revision/획득 기록을 함께 저장한다. 첫 선택 뒤에는 그 슬롯을 완료로 표시하고 다시 보충하지 않는다. R32는 추가 후보만 재추첨하며 예약 후보를 바꾸지 않는다. 나머지 포기는 확인 후 처리하고 B는 복구하지 않는다. 지역을 떠날 때 미수령 A를 포기한다는 안내와 확인을 거친다. 실제 부활은 예약을 유지하고 최종 사망/탐험 포기는 종료한다.

기본 보상과 R34는 최초 생성 슬롯 수를 유지한다. 후보 부족은 가능한 후보와금화15 대안을 제공하며 R47의 부분 보상에는금화 대안을 제공하지 않는다. 상품/선택 확정 시 현재 조건·reservation owner·revision을 재검사한다.

R48은 최초 적 목록을 방별로 저장하고 재진입할 때 앞의 최대2명을 재생성한다. 재전투 플래그로 금화/회복/영구 목표/새 유물 보상/최초 처치를 구분한다. 원래 적의 동결·화상·예약·HP를 복사하지 않는다. R48 상실 시 이미 시작한 재전투는 끝까지 진행하고, 이후 새 재전투는 시작하지 않는다. 최초 클리어 상태와 이미 지급한 보상은 유지한다.

## 7. 해금과 성장 연결

새 유물은 기획서의 해금 조건으로 획득 가능해야 한다. 기존 유물은 새 조건으로 다시 잠그지 않는다. 새 탐험의 해금 풀을 출발 시 스냅샷으로 기록하고 이후 목표 달성은 다음 탐험부터 반영한다. 구 탐험에 스냅샷이 없으면 기존27종의 현재 허용 규칙을 계속 사용한다.

초기 공개되는 새 유물은 R06/R09/R10/R19/R21/R22/R23/R24/R31/R37/R39/R40/R41/R42다. 조건부 신규 ID는 다음과 같다.

| 목표 | 조건 | 이번에 해금하는 ID |
|---|---|---|
| G02 | 최초 일반방 클리어 누적5회 | R14/R15 |
| G03 | 문지기 첫 처치 | R16/R17 |
| G04 | 사제 첫 처치 | R18 |
| G05 | 심장 첫 처치 | R26/R27 |
| G06 | 서로 다른 유물12종 획득 | R28/R29 |
| G07 | 서로 다른 유물24종 획득 | R32 |
| G08 | 서로 다른 보조 기술3종 성공 사용 | R33/R34 |
| G09 | 상점 구매 누적5회 | R35/R36 |
| G12 | 저주 획득 없이 최종 보스 처치 | R47/R48 |

새 유물의 선행 조건을 성립시키기 위해 부족한 G07/G08/G10/G11/G12를 추가한다. G10은 서로 다른 저주3종 실제 획득, G11은 탐험ID+지역+잠금방ID가 다른 최초 개방3회다. 원본의 G10/G11 보상 ID는 현재의 기존 유물이므로 이를 다시 잠그거나 지급하지 않는다. 목표별5점·합계최대60점으로 기존 획득 포인트를 확장한다. 현재 능력별 투자상한60은 유지한다.

기존 프로필의7개 목표는 같은 기록에서 인정하고, 새 누적 사용/잠금방/무저주 승리 이력은 실제 사건이 있을 때만 추가한다. 과거 데이터만으로 증명할 수 없는 신규 목표를 임의 완료시키지 않는다. G12는 마지막 보유 상태가 아니라 탐험의 저주 획득 이력으로 판정한다. 기존 R43/R38과 새로운 저주7종을 같은 분류 함수로 판단한다. G08은 R13/R16/R17의 성공 사용으로 도달하므로 해금 순환이 없다.

## 8. 저장과 원자성

IndexedDB 이름과 schema1을 유지하고 새 콘텐츠 버전 `prototype-0.14`를 추가한다. 기존0.1~0.13을 읽는 검증 경로를 유지한다. 새 상태는 선택 필드/콘텐츠 버전으로 검증하며 잘못된 구조는 적용 전에 거부한다. 미래 콘텐츠 버전을 자동 덮어쓰지 않는다.

저장할 새 데이터는 효과 타이머/발사 누적/공전탄, 설치 벽·미끼·중력·가시·닻·포털, 아군 진영/원래ID/HP/잔여시간, 휴대품 FIFO/사용 진행, 은신·회피 잠금·흡수 에너지, 최초 방 적 목록·재전투 구분, 구덩이·마지막 안전 위치, 바닥 pickup 상태, 잠금문/목표 이력, 해금 풀, R32 잔량, R47 reservation/부분 선택/포기 보상/revision이다.

정규화는 읽은 디스크 값을 수정·저장하기 전에 순수 복사로 수행한다. 기존 필드 없는 저장은 효과 없음/진행0으로 해석한다. 기존 R13/R43 재사용 필드는 원래 값으로 유지하고 새 보조 기술은 ID별 쿨다운 맵을 사용한다. UI의 선택 가능한 보조ID와 저장 검증이 같은 목록을 참조한다. 기술 교체/유물 상실/부활로 기존 쿨다운이 초기화되지 않는다.

상자 선택, 상품 결제, 열쇠 개방, pickup 수집, 회복 완료, 왕관 획득/부분 선택, 목표 지급은 각각 인벤토리·자원·조건·이력·난수 상태를 일관된 스냅샷으로 저장한다. 기존 불변 스냅샷·순차 쓰기·expected revision 충돌 처리를 유지한다. 같은 저장/재접속/방 재방문에서 자원을 재지급하지 않는다.

## 9. UI와 렌더링

인벤토리·상점·제단·보상 카드에 새 이름/등급/효과/등장 불가 사유와 필요한 해금 조건을 표시한다. 보조 슬롯은 기존1개이며 비전투에서 교체한다. 새 기술별 대기, R32 잔량, 휴대 회복량/시전 취소, R19 재생, 은신/흡수/닻/부분 포털, R47 두 보상과남은 선택을 HUD/기술 패널에 표시한다. F키 회복품 사용을 조작 안내에 추가한다.

World는 논리 효과를 고정 ID별 객체로 생성/갱신/회수한다. 아군은 소속을 읽을 수 있는 색·표식을 사용하고 원래 적 모델을 재사용한다. 잠금문·구덩이·픽업·벽·포털·광선·번개는 충돌 크기와 맞춰 표시한다. 자동/낮음에서 장식은 줄여도 공격 위험·유물 대가·지형 경계는 표시한다. 방 이동·상실·종료 후 GPU 자원을 해제한다. 기존 석재/무기 GLB와 화질 조절을 유지한다.

## 10. 성능과 검증 기준

현재 적 최대10명과 R17 전환1명을 같은 원래 적 예산 안에 둔다. 보조 생성 탄환120(공전 중 포함), 플레이어 기본탄80, 적탄160, 설치벽1·미끼1·중력1·가시2·포털1쌍을 생성 전에 검사한다. 가득 찼을 때 새 보조 효과를 생략/기술을 거부하고 이유를 표시하며 기본 사격이나 이미 살아 있는 피해 개체를 임의 삭제하지 않는다. 각종 타깃 순회는 현재 방의 개체를 대상으로 제한한다. 장식은 별도 한도로 재사용한다.

단위 검증은30종의 정상 효과/실패 조건/재사용 경계, 발사 이벤트와 산탄 상한, 피해 출처 전파, 보스 무적/방패/기둥, 아군 종료·소환취소·클리어 지연, 동적 충돌/설치 경로, 낙하/안전 착지, 가격 소수·할인·피격 제외, FIFO회복 취소, 포털 왕복 상한, 은신/흡수/충전 정지, 해금 도달성, 부분 왕관/예약/재추첨, 재전투 무보상, 저장 변조/결정성/기존 버전 호환을 다룬다. 구현과 같은 코드만 반복하는 테스트는 추가하지 않는다.

브라우저 검증은 실제30종 후보/획득·보조교체·F사용·잠금문·아군·설치물·포털·보상예약/두 선택/재접속·R48 재진입을 대표 조합으로 확인한다. 640×480 UI 접근, 위험 표시와 렌더 위치, 반복 방 이동의 GPU 자원 회수도 확인한다. 제품 파일 편집과 브라우저 회귀 실행을 겹치지 않는다. 마지막 전체 단위/타입/빌드와 변경에 필요한 브라우저 검사를 실행하고 각 실행 범위를 기록한다.

실기기60FPS는 이번 코드 검증만으로 보장하지 않는다. 자동 화질·프레임 독립성·개체상한을 유지하고 실제 구형 내장 그래픽의 p95 16.7ms 측정은 별도 결과로 보고한다.

## 11. 완료 조건과 단계 인계

30개 ID가 모두 실제 구현되어 획득 가능한 경로를 갖고, 효과/시각/저장/해금이 일치해야 완료다. 지원 기능이 없어서 효과가 발동하지 않는 카드나 영구적으로 획득 불가능한 유물을 완료로 세지 않는다. 기존27종과 구 저장 회귀를 통과하고 README/IMPLEMENTATION에 적용한 원본 차이·콘텐츠 수·검증 범위를 기록한다.

의존성 순서는 공통 데이터/저장 계약 → 지원 지형/픽업/목표/보상 구조 → 전투·방어·이동 → 설치물/아군/보조·저주 → UI/렌더링/통합 검증이다. 각 계열은 순수 규칙 모듈로 분리해 독립적으로 검증하고 동일 상태 인터페이스로 통합한다.

이 문서 승인 후 구현 계획을 작성한다. 이 프로젝트에는 Git 저장소가 없으므로 설계 문서를 작업 폴더에 보존하고 임의 저장소/커밋을 만들지 않는다. 구현 전 대상 소스·저장 fixture의 복구 가능한 백업을 보관한다.
